## 凡例

### 要件の由来の区別

本台帳では、要件の「由来」を次の3層に分けて記録します。

| 由来 | 意味 | ID体系 |
| :--- | :--- | :--- |
| 原始要件に明記された要件 | `docs/requirements/bank-system-requirements.md` に直接記載された事項 | REQ-xxx |
| 原始要件から導出される不変条件 | 複数の原始要件から導出される不変条件（原始要件に直接記載はない） | REQ-DOM-xxx（「導出不変条件」と明記） |
| 新たに決定が必要な提案 | 原始要件に存在しないが実装に必要な事項（不足・指摘） | GAP-xxx / DEC-xxx / ADR-CANDIDATE-xxx |

> 原始要件に存在しない新規要求を、既存要件（REQ-xxx）と同列に追加しません。

### 状態（State）

| 状態 | 意味 |
| :--- | :--- |
| Defined | 原始要件で明確に定義されている |
| Derived | 原始要件から導出される不変条件（原始要件に直接の記載はない。仕様書での明文化が前提） |
| Ambiguous | 複数の解釈が可能で確定が必要 |
| Conflicting | 原始要件の別箇所または他の正本と矛盾 |

> `Missing Decision` は「複数の選択肢からKooの判断が必要」な場合に限り使用する。決定不足と文書化不足（仕様への明文化が必要なだけ）は区別する（Agent Bレビュー m-1 反映）。

### 分類（Type）

機能 / 制約 / 不変条件 / 非機能
