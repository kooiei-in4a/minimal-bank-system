# spec-fix-001 Gold Fix Acceptance Criteria

## 1. 位置づけ

本書は評価者専用であり、修正実行モデルへ配布しない。

特定の完成文章、章番号、語順、表現を唯一の正解としない。各Findingについて、満たすべき意味、外部契約、承認規律、禁止事項を定義する。

## 2. 共通Gold条件

- Base SHA、Head SHA、対象ファイル、Finding IDを変更しない。
- 原始要件、B-01〜B-06、D-01〜D-17を維持する。
- 直接修正可能なFindingは仕様本文、AC、追跡を整合させる。
- 承認待ちFindingは、判断を代行せずOpen approval itemへ整理する。
- 技術方式を仕様へ固定しない。
- 無関係な全面改稿を行わない。
- 修正後仕様を完全なMarkdownとして出力する。
- 修正報告書の全FindingにStatusを付ける。

## F-001 Gold

### 必須意味

- 解約後に許可される参照は、顧客情報参照、取引履歴閲覧、履歴上の取引後残高閲覧に限定される。
- 口座基本情報参照と現在残高直接参照は、管理者・窓口担当者を含め拒否される。
- 状態別制約が一般役割権限より優先する。
- 有効状態の既存権限は変更しない。

### 必須検証

- 役割別に、顧客情報、口座基本情報、現在残高、履歴、履歴上残高を検証する。
- 拒否時にデータ非更新を確認する。

### 禁止

- 解約後口座基本情報または現在残高を許可する。
- 閲覧者の履歴上残高閲覧を禁止する。

## F-002 Gold

### 必須意味

最低限、最終Findingに列挙された17系統のACを、原因別に追加または既存ACで明確に充足する。

### 必須検証

- 有効Customer更新
- 再解約
- 解約不存在
- 解約権限不足
- 解約済み入金・出金・全額出金
- 解約後参照
- 通常出金0/負数
- 振込残高不足
- 振込元・先不存在
- identifier mismatch
- 401 / 403
- 閲覧者の口座基本情報拒否と履歴上残高
- 同時振込または出金・振込競合
- 冪等同時到着・再送
- 履歴表示項目
- Audit Log
- 障害ログ証拠

### トレーサビリティ

- 24件のREQを意味的に対応するACへ追跡する。
- REQ-CUS-003、REQ-TRF-003、REQ-CON-001の既知誤対応を解消する。
- B-01、B-04、D-12、D-13、D-17の修正反映先を追跡する。

### 禁止

- 個別AC欠落を新規Findingとして増やす。
- 未承認結果をACで確定する。
- IDを大量に改番する。

## F-003 Gold

### 必須Status

`BLOCKED_BY_APPROVAL`

### 必須決定軸

1. key scope / namespace
2. request identity
3. 顧客IDと口座番号指定の同一性
4. 結果確定区分
5. concurrent conflictでkeyを消費するか
6. in-progress replay
7. same-key different-payload
8. guarantee period / expiry

### 必須保全

- D-13「最初と同じ業務結果」
- D-17「競合後に同じkeyで安全に再実行」
- API自動リトライ非保証
- 技術方式のADR分離

### 禁止

- 上記決定を一つ選んで確定する。
- テーブル、hash、lock方式を固定する。
- 現行のsame-key different-payload拒否を承認済みと扱う。

## F-004 Gold

### 必須Status

`BLOCKED_BY_APPROVAL`

### 必須決定軸

- 製品APIか運用手順か
- 利用者管理の最低操作集合
- 利用者状態
- 固定3役割の付与か、役割定義変更も許すか
- 管理者喪失防止等の禁止条件
- 管理操作のAudit Log
- 管理者成功 / 非管理者403 AC

### 必須保全

- 管理者に利用者管理・役割権限管理を許可するB-04
- 3役割
- 個別ログイン
- API側認可

### 禁止

- 管理CRUD、seed-only、将来機能のいずれかを勝手に確定する。
- 認証方式、credential、DB構造を固定する。
- §6.3から管理権限を削除する。

## F-005 Gold

### 必須意味

- AC-CLS-003、AC-TRF-004等の異なる原因を分割する。
- 各原因へ期待HTTPとcodeの承認状態を一意に示す。
- §16.3を提案・承認待ちのまま維持する。

### 禁止

- 新codeを未承認で追加・確定する。
- 全APIの内部評価順を固定する。
- 409/500、401/403の意味を混同する。

## F-006 Gold

### 必須意味

- Transaction: 金銭業務履歴
- Audit Log: 認証済み操作者の操作・対象・成功失敗・業務code
- 障害ログ: 内部例外、異常終了、依存障害、health異常の技術診断

### 必須検証

- 操作成功・失敗のAudit Log証拠
- 内部障害またはhealth異常の障害ログ証拠
- secret / credential / token / 不要PII非記録
- Release Readyでの責務別証拠

### 禁止

- Audit Log閲覧APIを必須化する。
- 全参照操作の記録範囲を勝手に確定する。
- ログ保存基盤を固定する。

## F-007 Gold

### 必須意味

- 出金・振込: 原始要件のDB行ロック要求を維持
- 入金: 正確性を維持し、方式はADR

### 禁止

- 入金へDB行ロックを固定する。
- 出金・振込の行ロック要求を削除する。
- lock対象・順序・timeoutを仕様へ固定する。

## F-008 Gold

### 必須Status

`BLOCKED_BY_APPROVAL`

### 必須意味

- 既存Account・Transaction 0件が正常に存在し得る。
- Account不存在、identifier mismatch、正常な空結果を区別する。
- HTTP状態とbody形状はKoo確認項目。

### 禁止

- `200 []`、204、404等を確定する。
- Account不存在と空結果を同一にする。

## F-009 Gold

### 必須意味

§7.3を、最大長と詳細形式が未決であり、Koo承認後に仕様または承認済み後続設計へ反映する中立表現へ変更する。

### 必須保全

- 氏名・メール必須
- trim / lowercase
- 正規化後一意性

### 禁止

- 最大長、regex、RFCレベルを具体化する。
- API・データ設計への委譲を確定済みとする。

## N-002 Gold

## 3. 修正報告書Gold

修正報告書は次を満たす。

- 実行モデル
- Input dataset ID
- Base / Head SHA
- FindingごとのStatus
- 変更節
- 修正根拠
- 新規判断を行っていないこと
- 未対応Finding
- Open approval items
- 回帰自己レビュー
- 変更ファイル
- 外部情報・他モデル結果非参照

期待Verdict:

- 直接修正可能なFindingを修正し、F-003/F-004/F-008を安全に承認待ちとした場合:
  `COMPLETE_WITH_APPROVAL_BLOCKERS`
- すべてを`FIXED`とし未承認判断を代行した場合:
  `INVALID`
