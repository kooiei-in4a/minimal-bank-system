### Major

#### M-1 主要異常系のAcceptance Criteriaが不足し、検証可能性を満たさない

- 根拠:
  - 原始要件 §2.3 / REQ-TRF-003は、振込の残高不足、振込先不存在、解約済み、自己振込を主要異常として定義している。
  - Issue #7 §9は、解約について「解約成功・残高正数・残高負数・既解約・対象不存在・権限不足を受入条件へ含める」と要求している。
  - Issue #5 B-01は、解約済み口座への入金・出金・振込元利用の拒否を決定している。
  - 仕様書 §18 のACを照合すると、AC-TRF-004は自己振込と解約済みを扱うが、振込の残高不足・出金元/振込先不存在のACがない。解約ACは成功・正残高・負残高/不整合・再有効化禁止に留まり、既解約・対象不存在がない。入金ACは境界と並行に偏り、解約済み口座への入金拒否ACがない。通常出金ACにも解約済み拒否がない。
- 問題:
  - 仕様本文（§5.3、§5.4、§10.5、§11.4、§12.5）には主要異常が書かれているが、Acceptance Criteriaがそれを検証可能な形で固定していない。
  - §19.1はREQ-TRF-003→AC-TRF-004、REQ-CUS-005/006→AC-CLS系などと対応づけるが、対応先ACが要件の主要異常を実質的に覆っていない。
- 影響:
  - Specification Readyの「主要異常系」「受入条件」判定根拠が欠ける。
  - 実装・テストが正常系と一部境界に偏り、解約後操作や振込失敗経路で回帰を見逃す。
  - トレーサビリティ表が形式上完全でも、追跡の実効性が不足する。
- 修正方針:
  - 少なくとも次をGiven/When/Thenで追加する。
    1. 振込の残高不足で`insufficient_balance`、残高・履歴不変
    2. 振込の出金元または振込先不存在で404系固定コード、変更なし
    3. 解約済み口座への入金拒否、通常出金拒否（振込元はAC-TRF-004と合わせて明示）
    4. 既解約顧客/口座への解約再実行拒否、対象不存在での解約拒否、権限不足での解約拒否
  - §19の対応表を、追加ACを指すよう更新し、名目的対応を解消する。

#### M-2 権限マトリクス上の「利用者管理」「役割・権限管理」に製品契約がない

- 根拠:
  - Issue #5 B-04は、管理者のみ「利用者管理」「役割・権限管理」を許可すると決定している。
  - 仕様書 §6.3 はその2行を転記している。
  - しかし §2.1 対象、§7〜§13 の操作定義、§18 Acceptance Criteria、§22.1 承認事項のいずれにも、これら操作の入力・成功結果・失敗結果・対象範囲がない。
- 問題:
  - 承認済み権限行だけが残り、観測可能な製品挙動が未定義である。
  - 「seedデータで初期ユーザーを置くだけ」と「REST APIとして利用者CRUDを提供する」など、互換でない実装解釈が成立する。
- 影響:
  - B-04の一部が仕様として固定されず、認証・認可まわりの実装範囲がぶれる。
  - Specification Ready前に、v0.1.0へ含める操作範囲を確定できない。
- 修正方針:
  - 次のいずれかへ明確化する。
    1. v0.1.0の製品操作として定義し、正常系・異常系・ACを追加する
    2. 初期ユーザー投入等の運用前提へ落とし、権限表の行を「初期構築・運用手順」へ再分類して製品API対象外と明記する
  - どちらにするかはKoo承認事項として §22.1 へ追加する。

### Minor

#### m-1 閲覧者権限ACが「口座基本情報参照」拒否を明示しない

- 根拠: §6.3は閲覧者の口座基本情報参照を拒否とする。AC-AUTH-001は現在残高直接参照と更新系操作の403を述べるが、口座基本情報参照を列挙しない。
- 問題: 権限差の受入条件がマトリクスと完全一致しない。
- 影響: 閲覧者向けAPIが口座番号・口座状態等を返す実装をACで止められない。
- 修正方針: AC-AUTH-001に口座基本情報参照の403を追加する。併せて「口座基本情報」の返却項目を仕様で定義する。

#### m-2 同時実行ACが出金に偏り、振込同時実行を直接検証しない

- 根拠: REQ-CON-001は出金・振込の同時実行を対象とする。AC-CON-001は複数出金のみ。振込並行は§12.4・§17にあるがACがない。
- 問題: 主要非機能要件の受入条件が片寄っている。
- 影響: 振込デッドロック回避後の観測結果（片方成功/双方失敗、残高非負）をACで固定できない。
- 修正方針: 同一出金元への並行振込、または振込と出金の競合をACへ追加する。

#### m-3 通常出金の負数・0円境界がACにない

- 根拠: §15.2とREQ-VAL-001/REQ-WDR-004は通常出金の負数・0円拒否を要求する。ACは残高不足と全額0円に寄り、通常出金の0/負数ACがない。
- 問題: 入金・振込には境界ACがある一方、通常出金だけ欠ける。
- 影響: 共通バリデーションの実装漏れを見逃しやすい。
- 修正方針: AC-WDR系に0円・負数で`amount_out_of_range`、変更なしを追加する。

#### m-4 同一冪等キー・異内容拒否の導出根拠が弱い

- 根拠: D-13は同一キー再送で最初の業務結果を返すことだけを決定している。仕様 §10.4 / §11.4 / §12.4 と AC-IDEM-002 は同一キー異内容を拒否と固定している。
- 問題: 実務上必要な補完だが、決定本文からの導出であることが明示されていない。
- 影響: 承認時に「独断補完」と見なされる、または異内容時に旧結果を返す実装解釈が残る余地がある。
- 修正方針: D-13からの必要導出として明記するか、§22.1の承認対象へ含める。
